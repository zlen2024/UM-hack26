# Refactor Worker Tool Calling Spec

## Why
The current agent architecture uses a custom JSON schema for the manager node to define a list of tasks for the worker node to execute. To align with industry standards and improve reliability, the workflow will be refactored to use native Tool Use (Function Calling) provided by the LLM API (ilmu.ai / OpenAI compatible).

## What Changes
- Refactor the `manager_node` to pass available tools to the LLM using the `tools` parameter instead of a custom JSON schema.
- Update the `manager_node` system prompt to instruct the model to use the provided tools directly via function calling.
- Refactor the `worker_node` to process `tool_calls` generated by the `manager_node`.
- Return tool execution results back to the LLM as `role: "tool"` messages, allowing the model to generate a final response based on the tool outputs.
- Update the `AgentState` to store the conversation history (`messages` list) to maintain context between tool calls and the final response.

## Impact
- Affected specs: Tool execution and LLM interaction in the customer service agent workflow.
- Affected code: `backend/agents/cs_agent.py`

## ADDED Requirements
### Requirement: Native Tool Calling
The system SHALL use the `tools` parameter when calling the LLM API to enable native function calling.

#### Scenario: Tool Execution
- **WHEN** the manager node determines an action is needed.
- **THEN** it returns a `tool_calls` array. The worker node executes these tools and appends the results as `role: "tool"` messages to the conversation state, returning control to the manager to generate the final response.

## MODIFIED Requirements
### Requirement: Manager Node Output
The manager node MUST NOT use a strict JSON schema (`MANAGER_SCHEMA`) to output tasks. Instead, it should rely on the LLM's native ability to generate `tool_calls`.

## REMOVED Requirements
### Requirement: Custom JSON Task Array
**Reason**: Replaced by native tool calling for better performance and standard compliance.
**Migration**: Remove `MANAGER_SCHEMA` and the custom parsing logic for tasks.
